# Part01: Generate a Key Pair and Open an Encrypted Private Key

[한국어](../../../../labs/lab04/part01/README.md) | **English**

Use OpenSSL to generate an RSA key pair, save the private key as an encrypted
PKCS#8 file, and write Python code to open it with a password you know. You
will use the encrypted key in [Part02](../part02/README.md) to request a server
certificate. Follow the [Lab04 guide](../README.md) for the Docker environment.

## Learning objectives

- Generate a random RSA private key with OpenSSL and export its public key.
- Decrypt an encrypted private-key file in Python and check that its public key
  matches the exported one.
- Find the OIDs (Object Identifiers) in the public key and PKCS#8 encryption
  parameters, and explain what each algorithm identifier describes.

## Materials and task

- [decrypt_key.py](../../../../labs/lab04/part01/decrypt_key.py): runnable lab code; **you must complete its `decrypt_key()` TODO yourself.**
- [check.py](../../../../labs/lab04/part01/check.py): optional check for the decryption function.

Implement `decrypt_key(encrypted_pem: bytes, password: bytes)` with the installed
`cryptography` library's `serialization.load_pem_private_key()`. The provided
`main()` reads the encrypted key and public-key files, asks for the password,
compares their public keys, and prints a `LAB04{...}` completion marker on
success. Let `ValueError` from the loader propagate when the password is wrong.
Keep the password and private key out of reports and the repository.

## Generate the files with OpenSSL

Run these commands at `/workspace` **inside the course container**. OpenSSL
prompts twice for the encryption password in the first command. Enter the same
password when the second command asks to open the encrypted key.

```console
mkdir -p labs/lab04/part01/output
umask 077
openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:2048 -quiet | \
  openssl pkcs8 -topk8 -v2 aes-256-cbc -v2prf hmacWithSHA256 -iter 200000 \
    -out labs/lab04/part01/output/private_encrypted.pem
openssl pkey -in labs/lab04/part01/output/private_encrypted.pem -pubout \
  -out labs/lab04/part01/output/public.pem
```

`genpkey` generates the private key; the pipe sends it directly to `pkcs8`,
which encrypts it before writing `private_encrypted.pem`. No unencrypted
private-key file is written. `pkey -pubout` derives `public.pem` from the
encrypted key after you enter its password. Keep both files for the code below
and keep `private_encrypted.pem` for Part02. `umask 077` restricts newly created
files to the current user.

## Inspect the OIDs and open the key

An **OID** is a dotted numeric identifier for an algorithm or other ASN.1
object. OpenSSL's ASN.1 output shows names for the OIDs stored in the public
key and encrypted PKCS#8 file. Look at the `OBJECT` rows for the RSA public-key
algorithm, PBES2, PBKDF2, the PBKDF2 PRF, and the encryption cipher. Locate
the salt and iteration count in nearby rows;
`INTEGER` shows the iteration count in hexadecimal. One `OCTET STRING` is the
salt and another is the AES IV. The third command maps the printed names to
numeric OIDs.

```console
openssl asn1parse -in labs/lab04/part01/output/public.pem -i | sed -n '1,5p'
openssl asn1parse -in labs/lab04/part01/output/private_encrypted.pem -i | sed -n '1,15p'
openssl list -objects | grep -E '^(rsaEncryption|PBES2|PBKDF2|hmacWithSHA256|AES-256-CBC)'
python3 labs/lab04/part01/decrypt_key.py
python3 labs/lab04/part01/check.py
```

The Python program asks for the same password. Before you implement the TODO,
it raises `NotImplementedError`. After implementation, it checks that the
decrypted key corresponds to `public.pem` and prints the completion marker.
Run the optional check after completing the TODO. The private key is decrypted
in memory; do not save a plaintext copy.

## Checkpoint questions

1. How are the public and private keys in an RSA key pair generated by
   `genpkey` related?
2. What do the OIDs for the RSA public key, PBES2, PBKDF2, the PRF, and AES identify?
3. How do the salt and iteration count affect opening a password-protected file?
